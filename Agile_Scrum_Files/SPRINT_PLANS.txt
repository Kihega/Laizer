## Sprint 0 — Setup & Foundation
**Dates:** Week 1 (Mon–Fri)
**Goal:** Get the development environment, monorepo, CI/CD pipeline, and Supabase project fully operational before writing a single app feature.

### Sprint Goal
> *"By the end of Sprint 0, every developer has a running local environment, the GitHub monorepo is scaffolded with `main` and `develop` branches, CI/CD workflows pass, and a basic Expo app renders on device."*

### Sprint 0 Tasks (Not Story Points — these are setup tasks)

| # | Task | Owner | Done When |
|---|------|-------|-----------|
| T-001 | Create GitHub repo `smss-monorepo`, set up `main` + `develop` branches with protection rules | Dev | Branches exist on remote with PR protection enabled |
| T-002 | Scaffold Turborepo monorepo with pnpm workspaces | Dev | `pnpm install` runs from root without errors |
| T-003 | Create Expo app in `apps/mobile` with TypeScript template | Dev | `pnpm dev` inside apps/mobile shows Expo Go QR code |

| T-006 | Configure Supabase RLS policies for all tables | Dev | Owner can't read another owner's data |
| T-007 | Set up GitHub Actions: `pr-checks.yml` and `deploy-production.yml` | Dev | PR to develop triggers lint check in GitHub Actions |
| T-008 | Configure Expo EAS project; create `development`, `preview`, `production` build profiles | Dev | `eas build --profile development` runs without error |
| T-009 | Create shared-types package with initial TypeScript interfaces | Dev | Types importable from `@smss/shared-types` |
| T-010 | Write project README with setup instructions | Dev | New developer can follow README and run the app |

## Sprint 1 — Authentication
**Dates:** Weeks 2–3
**Sprint Points:** 25
**Goal:** Both user types (owner and worker) can log in and be routed to their respective dashboards.

### Sprint Goal
> *"By the end of Sprint 1, an owner can register and log in, and a worker can authenticate using a Centre ID — each landing on their own dashboard home screen."*

### Sprint 1 Backlog

| Story ID | User Story | Points | Assigned To |
|---------|-----------|--------|------------|
| US-001 | Owner registration (email + password) | 3 | Dev |
| US-002 | Owner login | 2 | Dev |
| US-003 | Worker login with Centre ID | 5 | Dev |
| US-004 | Persistent login session (SecureStore) | 2 | Dev |
| US-005 | Logout functionality | 1 | Dev |
| US-073 | RLS policies enforced on all tables | 5 | Dev |
| US-075 | Global error message component | 3 | Dev |
| US-076 | Global loading state component | 2 | Dev |
| — | Auth screen UI (login + register screens) | 2 | Dev |

**Total: 25 points**

### Sprint 1 Acceptance Criteria Summary

- [ ] Owner can register with email + password; account appears in Supabase Auth
- [ ] Owner can log in and land on Owner Dashboard (even if empty)
- [ ] Worker enters Centre ID → validated against DB → if valid, logs in and lands on Worker Dashboard
- [ ] Invalid Centre ID shows a clear error message
- [ ] Closing and reopening the app keeps the user logged in
- [ ] Logout clears the session and returns to login screen
- [ ] All auth routes protected — unauthenticated users redirected to login

**Goal:** Workers can register and manage stock at their centre; owner can view stock across centres.

### Sprint Goal
> *"By end of Sprint 3, a worker can log into their centre and register stock items with quantity, unit, and price — and the owner can see all stock levels across all centres."*

### Sprint 3 Backlog

| Story ID | User Story | Points | Assigned To |
|---------|-----------|--------|------------|
| US-030 | Worker: register new stock item | 5 | Dev |
| US-031 | Worker: view list of stock items at centre | 3 | Dev |
| US-032 | Worker: update stock item quantity | 3 | Dev |
| US-036 | Worker: delete incorrect stock entry | 2 | Dev |
| US-034 | Owner: view stock levels across all centres | 5 | Dev |
| US-035 | Owner: live stock updates (Supabase Realtime) | 5 | Dev |
| — | Stock list sorting (by name / by quantity) | 3 | Dev |

**Total: 26 points**

### Sprint 3 Acceptance Criteria Summary

- [ ] Stock entry form: item name, quantity, unit (pcs/boxes dropdown), price in Tshs
- [ ] Quantity cannot be negative; price must be a valid positive number
- [ ] Stock list shows item name, qty, unit, price — sorted alphabetically by default
- [ ] Owner sees all centres' stock in a scrollable, filterable list

- [ ] Currency display formatted as "Tshs X,XXX"

## Sprint 4 — Service Provision Tracking
**Dates:** Weeks 8–9
**Sprint Points:** 27
**Goal:** Workers can log service events at their centre; totals auto-calculate.

### Sprint Goal
> *"By end of Sprint 4, a worker can fully log a customer service transaction — selecting service type, subtype, pages, and price — and see a running log of today's events at their centre."*

### Sprint 4 Backlog

| Story ID | User Story | Points | Assigned To |
|---------|-----------|--------|------------|
| US-040 | Worker: log a complete service event | 8 | Dev |
| US-041 | Auto-calculate total (pages × price/page) | 3 | Dev |
| US-042 | Service type selector (6 types) | 3 | Dev |
| US-043 | Service subtype selector (B&W / Colour) | 2 | Dev |
| US-044 | Worker: view today's service event log | 3 | Dev |
| US-046 | Worker: edit/delete service event | 3 | Dev |
| US-045 | Owner: view all service events across centres | 5 | Dev |

**Total: 27 points**

### Sprint 4 Acceptance Criteria Summary

- [ ] Service event form: type, subtype, pages, price/page, optional note
- [ ] Total amount updates in real-time as user types pages or price
- [ ] Submitted event appears immediately in worker's daily log
- [ ] Events timestamped and associated with logged-in worker + centre
- [ ] Owner can filter events by centre, date, and service type
- [ ] Edit/delete only available within 1 hour of submission (or with owner override)

### Sprint Goal

| US-062 | Worker: push notification on new notice | 3 | Dev |

**Total: 26 points**

### Sprint 5 Acceptance Criteria Summary

- [ ] Daily report shows: total service events by type, total revenue, most active service
- [ ] Weekly report aggregates 7 days of data per centre
