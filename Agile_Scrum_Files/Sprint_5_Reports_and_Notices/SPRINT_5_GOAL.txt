SPRINT GOAL
-----------
"By the end of Sprint 5, the owner has a working reports dashboard
showing daily and weekly service summaries per centre, and can send
notices and instructions to workers -- who receive them in a dedicated
inbox and are alerted via push notification."


WHAT WILL BE TRUE AT THE END OF THIS SPRINT
---------------------------------------------
  - Owner views a daily summary per centre: total events by type,
    total revenue in Tshs, most active service
  - Owner views a weekly summary aggregating 7 days of data per centre
  - Owner composes and sends a notice with title, body, and priority
    to all workers of a specific centre
  - Workers see all notices in an inbox, most recent first
  - Unread notices show a badge indicator (e.g. red dot or count)
  - Workers receive a push notification when a new notice arrives
  - Owner can mark a notice as Normal or Urgent before sending


STORIES IN THIS SPRINT
-----------------------

  US-050  Owner views daily summary report        8 points
  US-051  Owner views weekly summary report       5 points
  US-060  Owner sends notice to a centre          5 points
  US-061  Worker notice inbox screen              5 points
  US-062  Worker push notification on notice      3 points

  Total: 26 points


TECHNICAL NOTES FOR THE TEAM
------------------------------
  - Daily and weekly reports should use the daily_service_summary
    database view created in Sprint 0. If adjustments are needed to
    the view, update the view definition in Supabase.

  - Push notifications require:
      a. Worker saves their Expo push token to expo_push_tokens table
         on first login (or on each app launch to keep it current).
      b. Supabase Edge Function listens for INSERT on notices table
         and sends push via Expo Push API.
      c. Test with two physical devices or one device + Expo push tool.

  - Notice priority: store in the priority column as "normal" or "urgent".
    Urgent notices should display with a red accent or label in the inbox.

  - Read receipts: when a worker opens a notice, insert a record into
    notice_reads. The inbox screen should mark notices as read when opened.
