STATIONERY MANAGEMENT & SALES SYSTEM (SMSS)
Mobile-Based Business Operations Platform

PROJECT SUMMARY
Version 1.0 | May 2026
================================================================================


1. EXECUTIVE SUMMARY
--------------------

SMSS is a cross-platform mobile application designed to streamline the
day-to-day operations of a stationery business running across multiple
service centres. It gives the business owner a single dashboard to manage
centres, workers, stock inventory, and service-provision trends in real time,
while workers on the ground log transactions, manage stock, and receive
notices from the owner instantly.

Core problems the system solves:
  - Manual, paper-based record-keeping of stock across dispersed centres
  - No real-time visibility into service trends or worker activity
  - Slow, unreliable communication between the owner and centre workers


2. PROJECT GOALS AND OBJECTIVES
--------------------------------

Goal 1  : Centralised multi-centre management
          Success measure: Owner can add and manage 2 or more centres
          from a single account.

Goal 2  : Real-time stock tracking
          Success measure: Stock levels update the moment a worker
          enters a new item.

Goal 3  : Service event logging
          Success measure: Workers log photocopy, printing, and lamination
          events per customer transaction without paper.

Goal 4  : Owner-to-worker communication
          Success measure: Notices and instructions reach workers within
          5 seconds of being sent.

Goal 5  : Business insights
          Success measure: Owner views daily and weekly service-provision
          trend reports per centre.


3. USER ROLES AND CORE FEATURES
---------------------------------

OWNER / EMPLOYER
----------------
Module: Manage Centres
  - Add a new centre with name, centre number (e.g. STN001),
    centre ID, and location (e.g. Arusha University)
  - View the full list of centres
  - Edit centre details
  - Deactivate or delete a centre

Module: Manage Workers
  - Register a new worker with name, NIM, and phone number
  - Assign a worker to a specific centre
  - Transfer a worker from one centre to another
  - View all workers across all centres
  - Remove or deactivate a worker

Module: Reports Dashboard
  - View daily and weekly service summaries per centre
  - View stock levels across all centres in real time
  - View service-provision trends by type (printing, scanning, etc.)
  - Filter reports by date range and centre

Module: Communication
  - Compose and send instructions or notices to workers
    of a specific centre
  - Mark a notice as normal or urgent
  - View read receipts per notice

WORKER / EMPLOYEE
-----------------
Module: Authentication
  - Log in using the assigned Centre ID

Module: Stock Management
  - Register a new stock item with name, quantity
    (in pieces or boxes), and net price in Tanzanian Shillings
  - View all stock items at their centre
  - Update stock quantities
  - Remove incorrect entries

Module: Service Provision Logging
  - Log a customer service event:
      Service type  : photocopy / printing / lamination /
                      scanning / designing / other
      Sub-type      : black and white / colour
      Pages         : number of pages
      Price per page: amount in Tshs (total auto-calculated)
  - View today's service event log at their centre

Module: Notices
  - View instructions and notices sent by the owner
  - Receive push notifications when a new notice arrives


4. RECOMMENDED TECHNOLOGY STACK
---------------------------------

Selection principle: favour tools that maximise development speed,
reduce infrastructure overhead, and support fast iteration.

MOBILE FRONTEND
  Framework       : React Native with Expo (Managed Workflow)
                    Single codebase for Android and iOS. Expo's built-in
                    modules remove native setup friction. Over-the-air
                    updates avoid app store resubmission for minor fixes.
  Language        : TypeScript throughout
  Navigation      : Expo Router v3 (file-based, like Next.js)
  UI components   : React Native Paper + NativeWind (Tailwind CSS)
  State management: Zustand (lightweight, minimal boilerplate)
  Forms           : React Hook Form + Zod schema validation
  Charts          : Victory Native XL (performant trend charts)
  Notifications   : Expo Notifications (push on Android and iOS)

BACKEND AND DATABASE
  Backend service : Supabase
                    Provides PostgreSQL database, authentication,
                    real-time subscriptions, file storage, and serverless
                    edge functions in one managed platform — no separate
                    server to build or host.
  Database        : PostgreSQL via Supabase with Row-Level Security
  Authentication  : Supabase Auth (JWT tokens, custom role claims)
  Real-time       : Supabase Realtime (WebSocket subscriptions)
  Storage         : Supabase Storage (future receipts and documents)
  Edge functions  : Supabase Edge Functions on Deno
                    (push notification dispatch, scheduled reports)

DEVELOPMENT INFRASTRUCTURE
  Monorepo tool   : Turborepo (fast incremental builds)
  Version control : Git + GitHub
  CI/CD           : GitHub Actions + Expo EAS
  Code quality    : ESLint + Prettier + Husky pre-commit hooks
  Testing         : Jest + React Native Testing Library
  API client      : Supabase JS Client + TanStack React Query
  Package manager : pnpm

DEPLOYMENT AND HOSTING
  Mobile app      : Expo EAS Build and EAS Submit
                    (cloud builds submitted to Google Play and Apple App Store)
  Backend         : Supabase Cloud (Free tier, upgradeable to Pro)
  CI/CD trigger   : GitHub Actions — PR merged to main triggers
                    EAS production build automatically

6. GIT BRANCHING STRATEGY
---------------------------

  main      -- Production-ready code only. Protected branch.
    |
    develop  -- Active development integration branch
      |
      +-- feature/owner-centre-management
      +-- feature/worker-auth
      +-- feature/stock-management
      +-- feature/service-events
      +-- feature/reports-dashboard

Workflow:
  Step 1: Developer creates a feature branch from develop
  Step 2: Opens a Pull Request to develop (code review required)
  Step 3: At end of each sprint, develop is PR'd into main
  Step 4: Merge to main triggers GitHub Actions and EAS production build

8. NON-FUNCTIONAL REQUIREMENTS
--------------------------------

Performance   : All screens load within 2 seconds on a 3G connection
Offline       : Stock entry and service events queue locally when
                offline and sync to the server on reconnect
Security      : Role-based data access via Supabase RLS; JWT tokens;
                no plaintext passwords stored
Scalability   : Supabase supports horizontal scaling; the architecture
                supports adding new centre types or business locations
Currency      : All monetary values displayed in Tanzanian Shillings (Tshs)
