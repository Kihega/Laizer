================================================================================
STATIONERY MANAGEMENT & SALES SYSTEM (SMSS)
GitHub Monorepo Setup Guide
================================================================================

Version 1.1 | May 2026 (Updated: Turborepo removed, backend added)
================================================================================


OVERVIEW
---------
The GitHub repository is already created. This guide covers:
  - Confirming the branch structure is correct
  - Scaffolding the monorepo workspaces with pnpm (no extra tools)
  - Setting up the Express.js backend
  - Connecting to Supabase PostgreSQL via Prisma
  - Connecting to Upstash Redis
  - Configuring Render for backend hosting
  - Setting up GitHub Actions CI/CD

Branch structure:
  main     -- Production-ready. Protected. Merge via PR only.
  develop  -- Integration branch. All feature work merges here.
  feature/ -- Short-lived. One branch per task or user story.

PART 1 : CONFIRM BRANCH SETUP
================================================================================

STEP 1 : Verify Branches Exist on Remote
------------------------------------------
Since the repository is already created on GitHub, confirm both
branches exist and are protected.

On GitHub:
  1. Go to your repository
  2. Click the branch dropdown (shows "main" by default)
  3. Confirm "develop" is listed

If develop does not exist yet:
  git clone https://github.com/YOUR_USERNAME/smss-monorepo.git
  cd smss-monorepo
  git checkout -b develop
  git push -u origin develop


STEP 2 : Confirm Branch Protection Rules
------------------------------------------
Go to Settings --> Branches and confirm:

  For main:
    Require pull request before merging: ON
    Require approvals: 1
    Require status checks to pass: ON
    Do not allow bypassing: ON

  For develop:
    Require pull request before merging: ON
    Require approvals: 1

PART 2 : MONOREPO WORKSPACE SETUP (pnpm only, no extra tools)
================================================================================

STEP 3 : Install pnpm (if not already installed)
--------------------------------------------------
  npm install -g pnpm


STEP 4 : Create the Workspace Config
--------------------------------------
In the repository root, create the file pnpm-workspace.yaml:

  packages:
    - "apps/*"
    - "packages/*"


STEP 5 : Create the Root package.json
---------------------------------------
Create or update package.json in the repository root:

  {
    "name": "smss-monorepo",
    "private": true,
    "scripts": {
      "dev:mobile":   "pnpm --filter mobile dev",
      "dev:backend":  "pnpm --filter backend dev",
      "build:mobile": "pnpm --filter mobile build",
      "build:backend":"pnpm --filter backend build",
      "lint":         "pnpm -r lint",
      "test":         "pnpm -r test",
      "format":       "prettier --write \"**/*.{ts,tsx}\""
    },
    "devDependencies": {
      "prettier": "^3.0.0",
      "eslint": "^8.0.0",
      "typescript": "^5.0.0",
      "husky": "^9.0.0",
      "lint-staged": "^15.0.0"
    },
    "packageManager": "pnpm@9.0.0"
  }


STEP 6 : Create the Folder Structure
--------------------------------------
Run these commands from the repository root:

  mkdir -p apps/mobile
  mkdir -p apps/backend/src/routes
  mkdir -p apps/backend/src/middleware

PART 4 : EXPRESS.JS BACKEND
================================================================================

STEP 8 : Initialise the Backend Package
-----------------------------------------
  cd apps/backend
  pnpm init
  pnpm add express
  pnpm add @prisma/client ioredis jsonwebtoken bcrypt zod
  pnpm add -D typescript ts-node nodemon @types/express
      @types/node @types/jsonwebtoken @types/bcrypt prisma

Create tsconfig.json inside apps/backend:

  {
    "compilerOptions": {
      "target": "ES2020",
      "module": "commonjs",
      "rootDir": "src",
      "outDir": "dist",
      "strict": true,
      "esModuleInterop": true,
      "skipLibCheck": true
    },
    "include": ["src/**/*"],
    "exclude": ["node_modules", "dist"]
  }

Add these scripts to apps/backend/package.json:

  "scripts": {
    "dev":   "nodemon --watch src --ext ts --exec ts-node src/index.ts",
    "build": "tsc",
    "start": "node dist/index.js",
    "lint":  "eslint src/**/*.ts"
  }

  cd ../..


STEP 9 : Create the Backend Entry Point
-----------------------------------------
Create the file apps/backend/src/index.ts:

  import express from 'express'
  import { authRouter }     from './routes/auth.routes'
  import { centreRouter }   from './routes/centres.routes'
  import { workerRouter }   from './routes/workers.routes'
  import { stockRouter }    from './routes/stock.routes'
  import { serviceRouter }  from './routes/services.routes'
  import { noticeRouter }   from './routes/notices.routes'
  import { reportRouter }   from './routes/reports.routes'
  import { errorHandler }   from './middleware/errorHandler'

  const app = express()
  app.use(express.json())

  app.use('/api/v1/auth',     authRouter)
  app.use('/api/v1/centres',  centreRouter)
  app.use('/api/v1/workers',  workerRouter)
  app.use('/api/v1/stock',    stockRouter)
  app.use('/api/v1/services', serviceRouter)
  app.use('/api/v1/notices',  noticeRouter)
  app.use('/api/v1/reports',  reportRouter)

  app.use(errorHandler)

  const PORT = process.env.PORT || 3000
  app.listen(PORT, () => console.log(`SMSS API running on port ${PORT}`))

PART 5 : SUPABASE POSTGRESQL + PRISMA
================================================================================

STEP 10 : Get the Supabase Connection String
----------------------------------------------
1. Go to https://supabase.com and open your project
2. Go to Settings --> Database
3. Copy the Connection String under "Connection pooling" mode
   (use the Transaction pooler URL for Prisma)
4. Also copy the Direct Connection URL (for migrations)


STEP 11 : Initialise Prisma
-----------------------------
  cd apps/backend
  pnpm prisma init

This creates prisma/schema.prisma and a .env file.


STEP 12 : Configure the Prisma Schema
---------------------------------------
Open apps/backend/prisma/schema.prisma and replace the content with
the full schema. Set the datasource block:

  generator client {
    provider = "prisma-client-js"
  }

  datasource db {
    provider  = "postgresql"
    url       = env("DATABASE_URL")
    directUrl = env("DIRECT_URL")
  }

Then add all 8 model definitions as listed in the Database Design
section of SYSTEM_ARCHITECTURE_AND_DATABASE_DESIGN.txt.


STEP 13 : Create and Apply the Migration
------------------------------------------
  cd apps/backend
  pnpm prisma migrate dev --name init

This generates a SQL migration file and runs it against Supabase.
All 8 tables are created.

To generate the Prisma Client (TypeScript types):
  pnpm prisma generate

To view the database in the browser:
  pnpm prisma studio


STEP 14 : Create the Prisma Client Singleton
---------------------------------------------
Create apps/backend/src/lib/prisma.ts:

  import { PrismaClient } from '@prisma/client'

  const globalForPrisma = globalThis as unknown as {
    prisma: PrismaClient | undefined
  }

  export const prisma = globalForPrisma.prisma ?? new PrismaClient()

  if (process.env.NODE_ENV !== 'production') {
    globalForPrisma.prisma = prisma
  }

PART 6 : UPSTASH REDIS
================================================================================

STEP 15 : Create an Upstash Redis Database
--------------------------------------------
1. Go to https://upstash.com and create an account (free)
2. Click "Create Database"
3. Settings:
     Name   : smss-redis
     Type   : Regional
     Region : Choose the closest to Tanzania (e.g. EU-West-1)
4. After creation, go to the database details page
5. Copy the "REDIS_URL" shown (starts with rediss://)


STEP 16 : Create the Redis Client
-----------------------------------
Add the REDIS_URL to your apps/backend/.env file.

Create apps/backend/src/lib/redis.ts:

  import Redis from 'ioredis'

  if (!process.env.REDIS_URL) {
    throw new Error('REDIS_URL environment variable is not set')
  }

  export const redis = new Redis(process.env.REDIS_URL)

  redis.on('connect', () => console.log('Redis connected'))
  redis.on('error', (err) => console.error('Redis error:', err))


STEP 17 : JWT Session Helpers
-------------------------------
Create apps/backend/src/utils/token.ts:

  import jwt from 'jsonwebtoken'
  import { redis } from '../lib/redis'
  import { v4 as uuidv4 } from 'uuid'

  const JWT_SECRET = process.env.JWT_SECRET!

  export async function signToken(
    payload: object,
    expiry: string
  ): Promise<string> {
    const jti = uuidv4()
    const token = jwt.sign({ ...payload, jti }, JWT_SECRET, {
      expiresIn: expiry
    })
    const decoded = jwt.decode(token) as { exp: number; sub: string }
    const ttl = decoded.exp - Math.floor(Date.now() / 1000)
    await redis.set(`session:${decoded.sub}:${jti}`, 'valid', 'EX', ttl)
    return token
  }

  export async function verifyToken(token: string) {
    const decoded = jwt.verify(token, JWT_SECRET) as {
      sub: string; jti: string; role: string; [key: string]: unknown
    }
    const session = await redis.get(`session:${decoded.sub}:${decoded.jti}`)
    if (!session) throw new Error('Session not found or has been revoked')
    return decoded
  }

  export async function revokeToken(
    userId: string,
    jti: string
  ): Promise<void> {
    await redis.del(`session:${userId}:${jti}`)
  }

PART 7 : RENDER DEPLOYMENT
================================================================================

STEP 18 : Create a Render Web Service
---------------------------------------
1. Go to https://render.com and sign in
2. Click "New" --> "Web Service"
3. Connect your GitHub account and select the smss-monorepo repository
4. Fill in the settings:
     Name             : smss-api
     Region           : Closest to Tanzania (e.g. Frankfurt)
     Branch           : main
     Root Directory   : apps/backend
     Runtime          : Node
     Build Command    : pnpm install && pnpm build
     Start Command    : node dist/index.js
     Instance Type    : Free

5. Under "Environment Variables", add all variables from your .env file:
     DATABASE_URL
     DIRECT_URL
     REDIS_URL
     JWT_SECRET
     JWT_OWNER_EXPIRY      (e.g. 7d)
     JWT_WORKER_EXPIRY     (e.g. 12h)
     NODE_ENV              production
     PORT                  (leave blank -- Render sets this automatically)

6. Click "Create Web Service"

Render will build and deploy the backend automatically.
After deployment, note the URL (e.g. https://smss-api.onrender.com)
Add this URL to apps/mobile/.env.local as EXPO_PUBLIC_API_URL.


STEP 19 : Enable Auto-Deploy from main Branch
-----------------------------------------------
In Render, go to your web service --> Settings --> Auto-Deploy.
Enable "Auto-Deploy" so every push to main triggers a redeploy.
This means merging the sprint PR (develop --> main) automatically
deploys the latest backend to Render.

PART 8 : GITHUB ACTIONS CI/CD
================================================================================

STEP 20 : PR Checks Workflow
------------------------------
Create .github/workflows/pr-checks.yml:

  name: PR Checks

  on:
    pull_request:
      branches:
        - develop
        - main

  jobs:
    lint-and-test:
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4

        - uses: pnpm/action-setup@v3
          with:
            version: 9

        - uses: actions/setup-node@v4
          with:
            node-version: '20'
            cache: 'pnpm'

        - run: pnpm install --frozen-lockfile
        - run: pnpm lint
        - run: pnpm test


STEP 21 : Production Deploy Workflow
--------------------------------------
Create .github/workflows/deploy-production.yml:

  name: Deploy to Production

  on:
    push:
      branches:
        - main

  jobs:
    deploy-mobile:
      name: EAS Mobile Build
      runs-on: ubuntu-latest
      steps:
        - uses: actions/checkout@v4

        - uses: pnpm/action-setup@v3
          with:
            version: 9

        - uses: actions/setup-node@v4
          with:
            node-version: '20'
            cache: 'pnpm'

        - run: pnpm install --frozen-lockfile

        - uses: expo/expo-github-action@v8
          with:
            eas-version: latest
            token: ${{ secrets.EXPO_TOKEN }}

        - name: EAS Android Production Build
          run: |
            cd apps/mobile
            eas build --platform android --profile production --non-interactive

  Note: Render auto-deploys the backend when main is updated.
        No separate GitHub Action is needed for the backend deploy.

Required GitHub Secret:
  EXPO_TOKEN  -->  Your Expo access token
                   Found at: expo.dev --> Account Settings --> Access Tokens

PART 10 : DAILY DEVELOPMENT WORKFLOW
================================================================================

STEP 23 : Working on a Feature
---------------------------------
Always start from an updated develop branch:

  git checkout develop
  git pull origin develop

Create a feature branch:

  git checkout -b feature/backend-auth-routes

Do your work. Run the backend locally:

  cd apps/backend
  pnpm dev         (starts nodemon on port 3000)

Run the mobile app locally:

  cd apps/mobile
  pnpm dev         (starts Expo Go QR code)

Commit and push:

  git add .
  git commit -m "feat: add owner login and JWT session to Redis"
  git push -u origin feature/backend-auth-routes

Open a Pull Request on GitHub: feature/* --> develop
After review and CI checks pass, merge and delete the feature branch.


STEP 24 : Sprint Release (develop into main)
---------------------------------------------
At the end of each sprint:

  1. Open a Pull Request on GitHub: develop --> main
  2. Title: "Release: Sprint X -- [Summary]"
  3. Add release notes listing all features completed
  4. Get one approval, then merge
  5. Render auto-deploys the backend from main
  6. GitHub Actions builds the updated Expo app for Android
