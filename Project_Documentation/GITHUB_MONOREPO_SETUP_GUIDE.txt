STATIONERY MANAGEMENT & SALES SYSTEM (SMSS)
GitHub Monorepo Setup Guide
================================================================================

Version 1.0 | May 2026
================================================================================


OVERVIEW
---------
This guide walks you through creating the GitHub repository, setting up local
branches, scaffolding the monorepo, and configuring CI/CD so that every merge
to main automatically triggers a production build.

Branch structure:
  main     -- Production-ready code only. Protected. Merge via PR only.
  develop  -- Integration branch. All feature work merges here first.
  feature/ -- Short-lived branches. Created per task or user story.


================================================================================
PART 1 : ONE-TIME GITHUB REPOSITORY SETUP
================================================================================

STEP 1 : Create the Remote Repository
---------------------------------------
1. Open https://github.com and sign in.
2. Click the "+" button (top right) then select "New repository".
3. Fill in the form:
     Repository name  : smss-monorepo
     Description      : Mobile-Based Stationery Management & Sales System
     Visibility       : Private
     Add README file  : Yes (tick the checkbox)
     Add .gitignore   : Select "Node" from the dropdown
4. Click "Create repository".


STEP 2 : Protect the main and develop Branches
------------------------------------------------
After the repository is created, do this for both branches.

  For the main branch:
    1. Go to Settings --> Branches --> Add branch protection rule
    2. Branch name pattern: main
    3. Enable: Require a pull request before merging
    4. Enable: Require approvals (set to 1)
    5. Enable: Require status checks to pass before merging
    6. Enable: Require branches to be up to date before merging
    7. Enable: Do not allow bypassing the above settings
    8. Click Save changes.

  For the develop branch:
    1. Click Add branch protection rule again
    2. Branch name pattern: develop
    3. Enable: Require a pull request before merging
    4. Enable: Require approvals (set to 1)
    5. Click Save changes.


================================================================================
PART 2 : LOCAL REPOSITORY SETUP
================================================================================

STEP 3 : Clone the Repo to Your Computer
------------------------------------------
Open a terminal and run:

    git clone https://github.com/YOUR_USERNAME/smss-monorepo.git
    cd smss-monorepo

Confirm you are on the main branch:

    git branch
    (Output should show: * main)


STEP 4 : Create the develop Branch Locally and on Remote
----------------------------------------------------------
    git checkout -b develop
    git push -u origin develop

Verify both branches now exist:

    git branch -a
    (Output should include: * develop, main, remotes/origin/develop,
                             remotes/origin/main)


================================================================================
PART 3 : MONOREPO SCAFFOLD
================================================================================

STEP 5 : Install pnpm (if not already installed)
--------------------------------------------------
    npm install -g pnpm


STEP 6 : Scaffold Turborepo
-----------------------------
Make sure you are on the develop branch:

    git checkout develop

Then run:

    pnpm dlx create-turbo@latest . --package-manager pnpm
    (When prompted, choose the "Empty" starter.)

Create the folder structure:

    mkdir -p apps/mobile
    mkdir -p packages/shared-types
    mkdir -p packages/supabase
    mkdir -p packages/config
    mkdir -p .github/workflows


STEP 7 : Configure Root Files
-------------------------------
Create the file pnpm-workspace.yaml at the root with this content:

    packages:
      - "apps/*"
      - "packages/*"

Create or update turbo.json at the root:

    {
      "$schema": "https://turbo.build/schema.json",
      "pipeline": {
        "build": {
          "dependsOn": ["^build"],
          "outputs": ["dist/**", ".expo/**"]
        },
        "dev": {
          "cache": false,
          "persistent": true
        },
        "lint": { "outputs": [] },
        "test": { "outputs": ["coverage/**"] }
      }
    }


STEP 8 : Create the Expo Mobile App
-------------------------------------
    cd apps/mobile
    pnpm dlx create-expo-app@latest . --template tabs

Install core dependencies:

    pnpm add @supabase/supabase-js
    pnpm add zustand
    pnpm add @tanstack/react-query
    pnpm add react-hook-form zod @hookform/resolvers
    pnpm add react-native-paper react-native-safe-area-context
    pnpm add expo-secure-store expo-sqlite expo-notifications

    cd ../..


================================================================================
PART 4 : GITHUB ACTIONS CI/CD WORKFLOWS
================================================================================

STEP 9 : PR Checks Workflow
-----------------------------
Create the file .github/workflows/pr-checks.yml with this content:

    name: PR Checks

    on:
      pull_request:
        branches:
          - develop
          - main

    jobs:
      lint-and-test:
        name: Lint and Test
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4

          - uses: pnpm/action-setup@v3
            with:
              version: 9

          - uses: actions/setup-node@v4
            with:
              node-version: '20'
              cache: 'pnpm'

          - run: pnpm install --frozen-lockfile
          - run: pnpm lint
          - run: pnpm test


STEP 10 : Production Deploy Workflow
--------------------------------------
Create the file .github/workflows/deploy-production.yml:

    name: Deploy to Production

    on:
      push:
        branches:
          - main

    jobs:
      deploy:
        name: EAS Production Build
        runs-on: ubuntu-latest
        steps:
          - uses: actions/checkout@v4

          - uses: pnpm/action-setup@v3
            with:
              version: 9

          - uses: actions/setup-node@v4
            with:
              node-version: '20'
              cache: 'pnpm'

          - run: pnpm install --frozen-lockfile

          - uses: expo/expo-github-action@v8
            with:
              eas-version: latest
              token: ${{ secrets.EXPO_TOKEN }}

          - name: Build for Android (production)
            run: |
              cd apps/mobile
              eas build --platform android --profile production --non-interactive

          - name: Build for iOS (production)
            run: |
              cd apps/mobile
              eas build --platform ios --profile production --non-interactive

IMPORTANT: Add your Expo token as a GitHub Secret.
  Go to: Repository --> Settings --> Secrets --> Actions --> New repository secret
  Name  : EXPO_TOKEN
  Value : Your Expo access token (from expo.dev --> Account Settings --> Access Tokens)


================================================================================
PART 5 : DAILY DEVELOPMENT WORKFLOW
================================================================================

STEP 11 : Working on a Feature
---------------------------------
Always start from a fresh develop branch:

    git checkout develop
    git pull origin develop

Create your feature branch:

    git checkout -b feature/owner-centre-management

Do your work, then commit:

    git add .
    git commit -m "feat: add centre creation form and API integration"

Push the branch to GitHub:

    git push -u origin feature/owner-centre-management

On GitHub: open a Pull Request from your feature branch into develop.
After code review and CI checks pass, merge and delete the feature branch.

Clean up locally:

    git checkout develop
    git pull origin develop
    git branch -d feature/owner-centre-management


STEP 12 : Commit Message Format (Conventional Commits)
---------------------------------------------------------
Use the following prefix format for all commit messages:

    feat:      New feature
    fix:       Bug fix
    chore:     Tooling or configuration change
    docs:      Documentation only
    refactor:  Code restructure with no behaviour change
    test:      Adding or updating tests
    style:     Formatting only, no logic changes

Examples:
    feat: add worker login with centre ID
    fix: correct stock quantity validation on submission
    chore: configure Husky pre-commit hooks
    docs: update README with local setup steps


STEP 13 : Sprint Release (develop into main)
---------------------------------------------
At the end of each sprint, open a release pull request on GitHub:

    From:   develop
    Into:   main
    Title:  Release: Sprint X -- [Brief summary of sprint]

Add release notes listing the features merged this sprint.
Get one approval from the Product Owner or a peer.
Merge the PR.
GitHub Actions will automatically trigger the EAS production build.


================================================================================
PART 6 : SUPABASE SETUP
================================================================================

STEP 14 : Create the Supabase Project
---------------------------------------
1. Go to https://supabase.com and sign in.
2. Click "New project".
3. Fill in:
     Name     : smss-production
     Password : Create a strong database password and save it securely
     Region   : Choose the region closest to Tanzania
                (East Africa is not listed; use Middle East Bahrain or
                 EU West as alternatives)
4. Wait for the project to be created (takes about 1 minute).
5. Go to Settings --> API and copy:
     Project URL    --> use as EXPO_PUBLIC_SUPABASE_URL
     Anon/public key --> use as EXPO_PUBLIC_SUPABASE_ANON_KEY


STEP 15 : Add Environment Variables
-------------------------------------
Create the file apps/mobile/.env.local and add:

    EXPO_PUBLIC_SUPABASE_URL=https://your-project-id.supabase.co
    EXPO_PUBLIC_SUPABASE_ANON_KEY=your-anon-key-here

Make sure .env.local is listed in your .gitignore file.
Never commit this file to GitHub.


================================================================================
SUMMARY OF BRANCH STRUCTURE
================================================================================

Remote (GitHub):
  origin/main      -- Production. Protected. Merge via PR only.
  origin/develop   -- Integration. Protected. Merge via PR only.
  origin/feature/* -- Short-lived. Created per task or story.

Local:
  main             -- Tracks origin/main
  develop          -- Tracks origin/develop. Your daily working base.
  feature/*        -- Your active work branch for each task.
