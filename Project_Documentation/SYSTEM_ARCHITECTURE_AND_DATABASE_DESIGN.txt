1. HIGH-LEVEL SYSTEM ARCHITECTURE
------------------------------------

The system is divided into three main layers:

  [CLIENT LAYER]
  +--------------------------+     +--------------------------+
  |   OWNER APP (Mobile)     |     |   WORKER APP (Mobile)    |
  |   React Native / Expo    |     |   React Native / Expo    |
  |                          |     |                          |
  |  - Centre Management     |     |  - Centre-ID Login       |
  |  - Worker Management     |     |  - Stock Management      |
  |  - Reports Dashboard     |     |  - Service Event Logger  |
  |  - Send Notices          |     |  - Notice Inbox          |
  +-----------+--------------+     +-----------+--------------+
              |                                |
              |       HTTPS / WebSocket        |
              v                                v
  [SUPABASE PLATFORM]
  +------------------+  +------------------+  +------------------+
  |  SUPABASE AUTH   |  | SUPABASE REALTIME|  | SUPABASE EDGE    |
  |                  |  |                  |  | FUNCTIONS        |
  |  - JWT Tokens    |  |  - Live Notices  |  |                  |
  |  - Role Claims   |  |  - Stock Sync    |  |  - Push Notifs   |
  |  - Centre-ID     |  |  - Event Feed    |  |  - Daily Reports |
  |    custom login  |  |                  |  |  - Cron Jobs     |
  +------------------+  +------------------+  +------------------+
              |                |                      |
              +----------------+----------------------+
                               |
                               v
  [DATABASE LAYER]
  +----------------------------------------------------------+
  |         POSTGRESQL DATABASE (Row-Level Security on)      |
  |                                                          |
  |  users, centres, worker_assignments, stock_items,        |
  |  service_events, notices, notice_reads,                  |
  |  expo_push_tokens                                        |
  +----------------------------------------------------------+

  [NOTIFICATION LAYER]
  +----------------------------------------------------------+
  |          EXPO PUSH NOTIFICATION SERVICE                  |
  |  Edge Function --> Expo Servers --> FCM/APNs --> Device  |
  +----------------------------------------------------------+


2. APPLICATION ARCHITECTURE PATTERN
--------------------------------------

The mobile app uses a Feature-Sliced Architecture inside the monorepo.

Layer             Responsibility
---------         -------------------------------------------------------
Screens           Expo Router pages. Minimal logic. Orchestrate components.
Components        Reusable, presentational UI elements.
Hooks             Business logic and data fetching (React Query + Supabase).
Stores            Global client state (Zustand) — auth session, UI state.
Services / Lib    Supabase client, helper functions, constants.
Types             Shared TypeScript interfaces from packages/shared-types.

Data Flow:
  User Action
      |
      v
  Screen (Expo Router)
      |
      v
  Custom Hook  (e.g. useStockItems, useServiceEvents)
      |    |-- React Query handles caching, loading, error states
      v
  Supabase JS Client
      |
      v
  Supabase  (PostgreSQL + Row-Level Security + Realtime)


3. AUTHENTICATION ARCHITECTURE
---------------------------------

Owner Login:
  Email + Password  -->  Supabase Auth  -->  JWT with role claim: "owner"

Worker Login:
  Centre ID  -->  Supabase Edge Function
             -->  Validate centre_id exists and worker is assigned
             -->  JWT with role claims: "worker" and centre_id: "STN001"

Row-Level Security Logic:
  Owners see only data belonging to their own centres.
  Workers see only data belonging to their assigned centre.
  Notices are only visible to workers of the target centre.


4. DATABASE DESIGN
--------------------

Entity Relationships:

  users  <---(owner_id)---  centres
  users  <---  worker_centre_assignments  --->  centres
  centres  --->  stock_items         (one centre, many items)
  centres  --->  service_events      (one centre, many events)
  centres  --->  notices             (one centre, many notices)
  users    --->  service_events      (one worker, many events)
  users    --->  notices             (one owner, many notices sent)
  notices  --->  notice_reads        (one notice, many read records)


TABLE: users
Purpose: Stores all application users (both owners and workers).

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key. Matches Supabase Auth UID.
  email                  text         Unique. Owner email address.
  phone                  text         Unique. Worker or owner phone number.
  full_name              text         Required. Full name of user.
  nim                    text         Unique. Worker employee number.
  role                   text         Required. Values: "owner" or "worker".
  is_active              boolean      Default true. Used for soft delete.
  created_at             timestamptz  Auto-set on record creation.
  updated_at             timestamptz  Auto-set on each update.


TABLE: centres
Purpose: Represents each physical stationery service centre.

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  centre_no              text         Unique. Business number e.g. STN001.
  centre_id              text         Unique. Worker login ID e.g. CENTRE-ARU-001.
  name                   text         Required. Display name.
  location               text         Required. E.g. "Arusha University".
  owner_id               uuid         Foreign key to users. Required.
  is_active              boolean      Default true. Soft delete.
  created_at             timestamptz  Auto-set.
  updated_at             timestamptz  Auto-set.


TABLE: worker_centre_assignments
Purpose: Maps workers to their assigned centres (many-to-many link).

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  worker_id              uuid         Foreign key to users.
  centre_id              uuid         Foreign key to centres.
  is_active              boolean      Default true. Marks current assignment.
  assigned_at            timestamptz  Auto-set when assignment is made.
  transferred_from       uuid         Nullable. Previous centre if transferred.


TABLE: stock_items
Purpose: Tracks all inventory stock items per centre.

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  centre_id              uuid         Foreign key to centres.
  registered_by          uuid         Foreign key to users (worker).
  item_name              text         Required. E.g. "Ink Pens", "A4 Paper Ream".
  quantity               numeric      Required. Must be 0 or greater.
  unit                   text         Required. Values: "pcs" or "boxes".
  net_stock_price_tshs   numeric      Required. Purchase price in Tshs. Must be >= 0.
  notes                  text         Optional. Additional notes.
  created_at             timestamptz  Auto-set.
  updated_at             timestamptz  Auto-set.


TABLE: service_events
Purpose: Logs each customer service transaction performed at a centre.

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  centre_id              uuid         Foreign key to centres.
  worker_id              uuid         Foreign key to users (worker).
  service_type           text         Required. Values: photocopy, printing,
                                      lamination, scanning, designing, other.
  service_subtype        text         Nullable. Values: "black_and_white" or "colour".
  category               text         Nullable. Additional classification.
  pages                  integer      Nullable. Number of pages. Must be >= 1.
  price_per_page_tshs    numeric      Nullable. Price per page in Tshs.
  total_amount_tshs      numeric      Required. Computed: pages x price_per_page.
  customer_note          text         Nullable. Optional customer reference.
  created_at             timestamptz  Auto-set. Transaction timestamp.


TABLE: notices
Purpose: Messages and instructions sent by the owner to workers of a centre.

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  sender_id              uuid         Foreign key to users (owner).
  centre_id              uuid         Foreign key to centres.
  title                  text         Required. Subject or headline.
  body                   text         Required. Full message content.
  priority               text         Default "normal". Values: low, normal, urgent.
  created_at             timestamptz  Auto-set.


TABLE: notice_reads
Purpose: Tracks which workers have read which notices.

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  notice_id              uuid         Foreign key to notices.
  worker_id              uuid         Foreign key to users.
  read_at                timestamptz  Auto-set when worker opens the notice.
  (unique constraint: one record per notice + worker combination)


TABLE: expo_push_tokens
Purpose: Stores device push tokens for delivering notifications.

  Column                 Type         Notes
  --------------------   ----------   ------------------------------------
  id                     uuid         Primary key.
  user_id                uuid         Foreign key to users.
  token                  text         Unique. Expo push token string.
  platform               text         Values: "ios" or "android".
  updated_at             timestamptz  Auto-set.


5. KEY DATABASE VIEWS
-----------------------

View: daily_service_summary
Purpose: Aggregates service revenue per centre per day per service type.
  Columns: centre_id, service_date, service_type, event_count,
           total_revenue_tshs

View: active_workers_per_centre
Purpose: Shows how many active workers each centre currently has.
  Columns: centre_id, centre_name, centre_no, active_worker_count


6. ROW-LEVEL SECURITY POLICY SUMMARY
---------------------------------------

Table                       Owner Access              Worker Access
--------------------------  ------------------------  -------------------------
centres                     Full CRUD on own centres  Read own assigned centre
worker_centre_assignments   Full CRUD on own centres  Read own assignment only
stock_items                 Read all in own centres   Full CRUD in own centre
service_events              Read all in own centres   Insert and Read in own centre
notices                     Full CRUD as sender       Read for their centre only
notice_reads                Read (delivery status)    Insert and Read own reads
expo_push_tokens            No access                 Insert and update own token


7. REAL-TIME SUBSCRIPTIONS
----------------------------

Event                       Channel                     Who Receives It
--------------------------  --------------------------  -------------------------
New notice sent             notices table INSERT        Workers of target centre
Stock item added            stock_items table INSERT    Owner dashboard
New service event logged    service_events table INSERT Owner dashboard (live feed)


8. PUSH NOTIFICATION FLOW
---------------------------

  Owner sends a notice
      |
      v
  Record inserted into notices table
      |
      v
  Supabase Edge Function triggered by database webhook
      |
      |-- Query: get all active workers for the target centre_id
      |-- Query: get their Expo push tokens from expo_push_tokens
      |
      v
  HTTP POST to Expo Push Notification API
  (https://exp.host/--/api/v2/push/send)
      |
      v
  FCM (Android) or APNs (iOS)
      |
      v
  Push notification appears on worker's device


9. OFFLINE STRATEGY
---------------------

Feature                 Offline Strategy
----------------------  -------------------------------------------------------
Stock entries           Queued in Expo SQLite on device. Synced to Supabase
                        automatically when internet connection is restored.
Service events          Queued in Expo SQLite. Batch-synced on reconnect.
Notices                 Cached by React Query. Last-fetched notices visible
                        even without connection.
Auth session            JWT stored in Expo SecureStore. Remains valid for
                        the full session duration.


10. ENVIRONMENT VARIABLES
---------------------------

The following variables must be set in the apps/mobile/.env.local file:

  EXPO_PUBLIC_SUPABASE_URL      The Supabase project URL
  EXPO_PUBLIC_SUPABASE_ANON_KEY The Supabase anonymous public key

The service role key (SUPABASE_SERVICE_ROLE_KEY) is used only inside
Edge Functions running on Supabase servers. It must never be included
in the mobile app or committed to version control.
